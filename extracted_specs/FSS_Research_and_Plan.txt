Failure Synthesis System
Research papers, drone logging standards & public data, and prototyping plan  |  Prepared 8 Oct 2026 for
mentor review
Key takeaways
• No IEEE standard defines an onboard drone flight-log format. IEEE 1936.1-2021 covers operation records
at a framework level; IEEE 1937.3-2024 covers supervision-data transmission. The de facto log standards are
autopilot formats: MAVLink 2, PX4 ULog, ArduPilot DataFlash, and MCAP.
• Real drone data is available: PX4 Flight Review public logs (CC-BY, bulk download), ALFA (real faults with
ground-truth timing), RflyMAD (11 fault types, 5,629 cases), and a cyber-physical swarm dataset.
• Gap: no public dataset found contains labelled cross-agent causal failure chains (the Drone 298 -> Drone 474
scenario). We must generate these ourselves in multi-vehicle simulation with fault injection. This gap is also a
defensible contribution.
• Design recommendation: use MAVLink message definitions as the payload-schema source for the
deterministic decoder (event_type = msgid). This gives a real, documented schema set, and unknown-msgid
handling maps directly onto our UNKNOWN_EVENT_TYPE rule.
• Prior art validates the architecture: per-record CRC framing (LevelDB, Kafka), segment/chunk time indexes
with index recovery from truncated files (MCAP), and two-stage collect-then-reason LLM RCA (RCACopilot).

transmission. None specifies an onboard event-log format or crash-recovery semantics. That gap supports the
project's motivation.
2.2 De facto logging formats used on real drones
Format
Structure (what matters for us)
How FSS uses it
MAVLink 2
mavlink.io
Binary telemetry protocol. Header carries seq, sysid
(vehicle), compid, a 24-bit msgid and payload length.
Messages are defined in XML. On the wire, fields are
reordered largest-first. A CRC-16/MCRF4XX is seeded
with a per-message CRC_EXTRA derived from the
definition, so a receiver can detect a schema mismatch.
Max packet 280 bytes.
Recommended payload-schema source. sysid
-> source_id, msgid -> event_type, XML -> decoder
schema. CRC_EXTRA is a ready-made
schema-version check. The Python decoder can
reuse pymavlink definitions.
PX4 ULog
docs.px4.io
Self-describing log of uORB topics: a 16-byte header,
then definitions ('F' format messages), then data. Every
subscribed format includes a timestamp field.
Source of realistic payloads. A ULog replayer
converts topics to EventRecords and streams them
into the Java ingest (parse with pyulog).
ArduPilot
DataFlash (.bin)
Self-describing: FMT records declare type id, length,
name, format string and column labels. Messages start
with header bytes 0xA3 0x95. Parsers can resync after
corruption by scanning for the next valid header.
Second replay source. Its resync-on-corruption
behaviour is a reference for our recovery scan.
MCAP
MCAP spec
Container for pub/sub messages: schemas and
channels embedded; chunks with message start/end
time and CRC; a summary index at the end;
nanosecond timestamps.
Design reference for segment/block metadata, and
an optional export format so logs open in Foxglove.

Gap: no dataset found has labelled cross-agent failure chains (agent A's fault causing agent B's behaviour).
Plan: generate these in PX4 SITL multi-vehicle simulation, inject faults on one vehicle, script the reaction on a
neighbour, and record the injected cause as ground truth. PX4 has a built-in failure-injection facility, but its exact
commands and parameters are still to be checked in the PX4 docs.
2.4 Notes for the design
• Both PX4 and ArduPilot logs are self-describing (format records inside the file). Our design keeps schemas
outside the store, in Python config. Be ready to explain to the mentor why: the store stays protocol-agnostic and
Java never interprets payloads.
• MAVLink's sysid is a natural source_id, and msgid (24-bit) fits a u32 event_type. Use MAVLink's mapping
rather than inventing one.
• ULog timestamps are in microseconds since boot, and MCAP uses nanoseconds. Fix u64 nanoseconds in our
envelope and store the clock basis (boot vs UTC) per source in metadata.
• MAVLink CRC_EXTRA is the precedent for a schema_version field: add it to DecodedEvent.

3. Next steps: prototyping plan
Ordering principle: freeze the contract first, run the Python layer and the Java core in parallel against shared
fixtures, and leave segment indexing until the simple store has been proven crash-safe.
3.1 Contract to freeze this week (v0)
Wire envelope (little-endian):
magic u16 | version u8 | flags u8 | source_id u32 | timestamp_ns u64 | event_type u32 |
payload_len u32 | payload[..]
On-disk record: record_len u32 | crc32c u32 | envelope bytes (crc covers len + envelope)
Block: fixed size (e.g. 64 KiB), zero-preallocated, single source, no record crosses a boundary
retrieve(source_id | ALL, t_start_ns, t_end_ns, event_type?, max_events) -> EventRecord[] +
truncated flag
Transport Java -> Python: gRPC or HTTP+JSON (payload base64); Python never opens store files
